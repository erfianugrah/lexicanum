title: "Labelling AI use in your own work: what 0rwx measures and what it leaves out"
description: "The 0rwx framework grades AI use by whether you can still read the work. Applied to 69 repos where 81% of commits in a 20-day window were made by a coding agent, and to the founding conversations of 16 projects, it records who produced the artifact but not who conceived it, how it was checked, whose domain knowledge it rests on, or what breaks if it is wrong. Compared with CRediT, IBM's AI Attribution statements, Amazon KDP, USPTO and US Copyright Office tests, and three open-source project policies, plus a per-axis label that keeps those apart."
author: Erfi Anugrah
category: workstations

The 0rwx framework labels a piece of work by how much AI was involved, in four levels borrowed from unix permissions.[^0rwx-site] This page applies it to my own repos, which a coding agent mostly writes, and lists what its single axis cannot express. It is for anyone who builds with an agent and wants a disclosure that says more than "AI made".

Provenance. Commit counts were measured on 2026-11-08 over the window 2026-10-20 to 2026-11-08, the span covered by the harness's git audit log ([Running agent git commands without per-command approval prompts](/reference/agent-git-without-prompts/)). Founding conversations come from the cross-client session store described in [A cross-client memory store for coding agents](/reference/agent-memory-store/), which holds pi, Claude Code, opencode and claude.ai chats back to 2024. Quotes in the origination tables were re-fetched by session and message number before publishing. The origination verdicts are mine and are judgments, not measurements.

**TL;DR:**

- 0rwx grades one thing: "your ability to scrutinise the generated work". By that test nearly everything here is AI:X, "YOU can no longer read your work". 2,307 of 2,857 commits in the window (81%) were made by the agent, and I do not read most diffs line by line.
- The founding conversations of 16 projects show I set the goal, the constraints and most of the architecture, including decisions that overruled the agent. One project, a word game, started from a design the agent proposed and I picked. 0rwx has no field for any of this.
- 0rwx treats reading as the only form of scrutiny. Here the checks are tests, CI, sensor-gated loops, build diffs before deploy, and using the result. 31 of the 69 repos have no test files, most of the deployment repos among them.
- Patent and copyright tests already separate conception from production, and CRediT separates Conceptualization from writing. KDP classifies the other way: an idea from AI with text written by you is "AI-assisted", text from AI that you edited heavily is "AI-generated".
- A label with one value per axis (idea, design, knowledge, build, check, stakes) describes this work. A single letter does not.

## The axes a label could record

```dot
digraph {
  rankdir=LR; bgcolor="transparent"; nodesep=0.3; ranksep=0.7;
  fontname="Helvetica,Arial,sans-serif";
  node [fontname="Helvetica,Arial,sans-serif", fontsize=11, shape=box];
  edge [fontname="Helvetica,Arial,sans-serif", fontsize=9];

  idea [label="Idea\nwhat problem, for whom"];
  design [label="Design\narchitecture, constraints"];
  knowledge [label="Domain knowledge\nwhose expertise"];
  build [label="Build\nwho wrote the artifact"];
  check [label="Check\nread, test, probe, use"];
  stakes [label="Stakes\nwhat breaks if wrong"];

  idea -> design -> build -> check;
  knowledge -> design;
  knowledge -> check [label="limits"];
  stakes -> check [label="sets how tight"];
}
```

1. Idea: who identified the problem and the goal.
2. Design: who chose the architecture and the constraints.
3. Domain knowledge: whose expertise the design and the checks rest on. It limits what can be checked.
4. Build: who produced the artifact. This is the only axis 0rwx grades, through whether you can still read the result.
5. Check: how the result was verified.
6. Stakes: what fails if the result is wrong, which sets how tight the check has to be.

| Scheme | Idea | Design | Knowledge | Build | Check | Stakes |
|---|---|---|---|---|---|---|
| 0rwx | only implied by levels 0 and R | no | no | yes (as readability) | reading only | no |
| CRediT | yes (Conceptualization) | yes (Methodology) | no | yes (Software, Writing) | yes (Validation) | no |
| IBM AI Attribution | no (records who triggered each AI contribution) | no | no | yes (human vs AI share) | yes (who reviewed and approved) | no |
| Amazon KDP | treated as minor | no | no | yes, decides the label | no | no |
| USPTO inventorship | yes, decides inventorship | yes | no | explicitly not enough | no | no |
| USCO copyrightability | prompts not enough | selection and arrangement | no | yes, decides protection | no | no |
| Ghostty policy | no | no | no | disclosed | human must understand all code | no |

Sources for each row are in [How other schemes split the axes](#how-other-schemes-split-the-axes) and the sections it links back to.

## 0rwx in brief

The site defines four levels, each with a phrase and a badge.[^0rwx-site]

| Level | Site definition | Phrase | Badge |
|---|---|---|---|
| AI:0 | AI can't read or write to your work | "I think" | HAND MADE |
| AI:R | AI has read-only permissions | "I make" | AI INSPIRED |
| AI:W | AI has read-write permissions | "I fix" | AI COLLABORATION |
| AI:X | YOU can no longer read your work | "I curate" | AI MADE |

The site states the axis directly: "The difference between the 4 levels is not necessarily about what TOOL you use, but your ability to scrutinise the generated work."[^0rwx-site]

The accompanying video grounds the scale in Lisanne Bainbridge's 1983 paper "Ironies of automation"[^bainbridge]: once automation does nearly all of the work, the operator's skill decays and their job becomes monitoring the machine.[^0rwx-video] From that, the video argues that at Claude Code levels of automation "people who say they read the code are lying to themselves", and that "Claude tested it for me doesn't cut it". It also cites Adam Savage on tolerances: professionals know when a corner can be cut, but only if they know a corner is being cut. For anyone who rejects the levels it offers credit wording instead: an AI research assistant at R, a co-writer when AI output ends up in the work, and "if the project was mostly AI written, own it". The project's repository asks for "no AI please" in issues and pull requests.[^0rwx-repo]

## Where 0rwx puts this setup

Per-repo counts from the commit history, with an agent commit defined as one made within 180 s after an audited agent `git commit` in the same repo. Four repos whose commits ran outside the audited path, two of them upstream forks, are excluded.

| Measure (2026-10-20 to 2026-11-08) | Value |
|---|---|
| Repos with commits in the window | 69 |
| Commits | 2,857 |
| Agent commits | 2,307 (81%) |
| Repos at or above 80% agent commits | 43 |
| Repos with test files | 38 |
| Repos with CI workflows | 44 |
| Repos with a sensor-gated loop manifest | 20 |

31 of the 69 repos have no test files. The deployment repos with the most commits are among them:

| Repo | Commits | Agent | Test files | CI workflows | Loop manifest |
|---|---|---|---|---|---|
| router (NixOS) | 43 | 95% | 0 | 0 | no |
| servarr-compose | 46 | 93% | 0 | 0 | yes |
| monitoring-compose | 31 | 94% | 0 | 0 | yes |
| servarr-nixos | 23 | 74% | 0 | 0 | no |
| dns-tf | 6 | 83% | 0 | 0 | no |

The two NixOS repos get a build diff of the activation plan before deploy. The loop manifests in the two compose repos drove a documentation split and a dashboard task, and check nothing about the running stack. Not every deployment repo lacks tests: the DNS resolver repo has 164 test files, and the edge proxy repo, which sits too deep in the directory tree for the scan and is not in the 69, has 63.

The scan covers git repos up to three directories below the home directory, so deeper nested repos are missing from every count. Commit proximity is not authorship. An agent commit can carry text I typed, a commit I made by hand can carry agent text, and Claude Code on another machine never reaches this audit log. The test counts include tests the agent wrote.

By 0rwx's own definition the answer is AI:X across most of the corpus.

A project usually starts as a question ("what are my options", "is there a way", "what would be a good stack"). The agent surveys, I decide, and the decisions that shape the project are mine.

## What 0rwx does not record

### Who conceived the work

The scale grades the artifact. A one-line "make me an app" and a project whose author set the architecture, overruled the agent's stack and specified a zero-input-latency budget both come out as AI:X, and the video's credit wording ("mostly AI written, own it") assigns credit by who produced the text.

Patent law draws the line elsewhere. The USPTO's 2024 guidance on AI-assisted inventions says "Reducing an invention to practice alone is not a significant contribution that rises to the level of inventorship", that "Merely recognizing a problem or having a general goal or research plan to pursue does not rise to the level of conception", and that "a significant contribution could be shown by the way the person constructs the prompt in view of a specific problem to elicit a particular solution".[^uspto-2024] Under that test the 0rwx level is beside the point. What counts is whether the human's contribution to the solution was significant.

Copyright draws it closer to 0rwx. The US Copyright Office's 2025 report concludes that "prompts do not alone provide sufficient control" over the output, while human selection, coordination or arrangement of AI output can be protected.[^usco-part2]

### Scrutiny other than reading

0rwx's W level is "I read the code" and its X level is "you can no longer read your work". Reading is the only check it names. The checks used here are test suites, CI, sensor-gated loops that iterate until objective checks pass ([Loop or graph: a sensor-gated coding-agent loop](/reference/self-correcting-agent-loop/)), a build diff of the activation plan before a router or NAS deploy, guards that block unverified specifics ([Guard extensions that enforce prose and process rules](/reference/agent-guard-extensions/)), and using the thing: 4 of 18 mid-project prompts in the first sample were a report of something broken in use, usually a screenshot.

The video's warning still applies to every one of those. A test written by the agent can pass while asserting the wrong thing, and "the agent tested it" is the sentence the video rejects. Being unable to read the code and being unable to check it are different states, and a label should say which checks exist.

### Whose domain knowledge it rests on

The real limit on checking is where the agent supplied expertise I lack: firmware glitching methods, a protocol's wire format, a decompiled plugin's maths. There I cannot judge the output even at AI:W, because reading it does not tell me whether it is right. In a domain I know, a wrong design shows in its behaviour. The closest any policy here comes is Ghostty's "The human-in-the-loop must fully understand all code".[^ghostty-policy] That asks for comprehension of the code, which a reader can have and still be wrong about the domain, and it says nothing about who typed it.

### What breaks if it is wrong

The video's tolerance argument has no slot in the labels. AI:X on a naming brainstorm and AI:X on the router configuration read the same, and several of the repos that change running systems have no tests. That is where the tolerance should be tightest.

### Mixed levels inside one work

In one repo the AGENTS.md design notes, the constraints and the acceptance are mine and the code is the agent's. In one session the level moves from R (asking how firmware glitching works) to X (a worker building the plugin). A per-project label averages this away. The unit that fits is the change or the component.

### The system that produced the work

I designed the harness the agent runs in: the guards, the skills, the gates and the routing rules ([The pi harness journey](/reference/pi-harness-journey/)). The USPTO guidance counts this kind of contribution too: "a person who designs, builds, or trains an AI system in view of a specific problem to elicit a particular solution could be an inventor".[^uspto-2024] 0rwx looks only at the final artifact.

### Time

Bainbridge's argument is about skill decay over time. A label is a snapshot and says nothing about whether the labeller can still do the work by hand.

### Disclosure

Grading AI use and disclosing it are separate decisions, and projects handle them separately. Ghostty requires "All AI usage in any form must be disclosed" from outside contributors and exempts its maintainers.[^ghostty-policy] The Linux kernel removed its `Assisted-by` trailer on 2026-10-09 after "The Maintainers Summit reached consensus to deprecate the Assisted-by tag".[^kernel-assisted-by] Gentoo has forbidden "any content that has been created with the assistance of Natural Language Processing artificial intelligence tools" since 2024-04-14.[^gentoo-ai] The harness described here bans AI-attribution trailers in commits, so the repos disclose nothing at any level; this page is the disclosure.

## How other schemes split the axes

CRediT, a contributor taxonomy journals use to credit co-authors, lists 14 roles, among them Conceptualization, Methodology, Software, Validation, and "Writing - original draft" separately from "Writing - review & editing".[^credit] It already separates the idea from the writing, though it was designed for human co-authors.

IBM Research's AI Attribution Toolkit, partly inspired by CRediT, generates a statement appended to a work from three questions: "How much work did the human do relative to the AI? What were the AI's contributions? Who reviewed and approved the final work?" Its own paper carries "This work was produced without AI assistance (AIA No AI 1.0)."[^ibm-aia] The toolkit also asks "Who initiated AI contributions?", where AI-initiated means "AI made proactive contributions without human request, such as auto-completed suggestions or additions".[^ibm-aia-src] That records who triggered each AI contribution, not who conceived the work. It records review, which 0rwx does not.

Amazon KDP asks authors to disclose AI-generated content and draws its line by production: content "created by an AI-based tool" is AI-generated "even if you applied substantial edits afterwards", while "if you used an AI-based tool to brainstorm and generate ideas, but ultimately created the text or images yourself, this is also considered 'AI-assisted'", which needs no disclosure.[^kdp] That is the reverse of the USPTO test: KDP treats the idea as minor and the production as decisive.

The USPTO and USCO tests and the three project policies are quoted in the sections above.

## A label with one value per axis

0rwx's letters work as values on each axis instead of one per work:

```
idea:0  design:0/R  knowledge:R/X  build:X  check:test+use  stakes:low|prod
```

| Axis | Value here | Meaning |
|---|---|---|
| idea | 0 | the problem and goal are mine |
| design | 0, R where I picked from agent proposals | architecture and constraints are mine; the word game is R |
| knowledge | R in domains I know, X where the agent sourced the expertise | X marks the parts I cannot judge |
| build | X | the agent writes the artifact |
| check | test, probe, use | named checks, not reading |
| stakes | low or prod, per repo | how tight the check must be |

## Decision guide

```dot
digraph {
  rankdir=TB; bgcolor="transparent"; nodesep=0.3; ranksep=0.5;
  fontname="Helvetica,Arial,sans-serif";
  node [fontname="Helvetica,Arial,sans-serif", fontsize=11, shape=box];
  edge [fontname="Helvetica,Arial,sans-serif", fontsize=9];

  q1 [label="Who is the label for?"];
  conv [label="A conversation about\nhow you work"];
  read [label="Readers of the artifact"];
  law [label="A patent or\ncopyright question"];
  rwx [label="One 0rwx letter\nis enough"];
  axes [label="Per-axis label:\nidea, design, knowledge,\nbuild, check, stakes"];
  legal [label="The conception test\n(USPTO) or selection and\narrangement (USCO)"];

  q1 -> conv; q1 -> read; q1 -> law;
  conv -> rwx;
  read -> axes;
  law -> legal;
}
```

1. A quick conversation about how you work with AI: one 0rwx letter is enough, which is the use the video intends.
2. Readers who will rely on the artifact: give the per-axis label, and name the checks and the stakes.
3. A patent or copyright question: the 0rwx level is not the test. Use the USPTO conception test or the USCO selection-and-arrangement test.
