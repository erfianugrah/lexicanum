A coding-agent harness built and maintained with the agent it constrains, from 2025-03 to 2026-10: per-repo instruction files until 2026-01, a shared harness from then on. This page is the hub of the series. It covers the timeline, the layout, where each guard runs, the extension and skill catalogue, and the lessons that hold outside this setup.

**TL;DR:**

- Claude Code with per-repo `CLAUDE.md` files from 2025-03, an opencode configuration (later a fork) from 2026-01, pi from 2026-05-21, opencode retired 2026-08-15. Claude Code came back as a second harness on 2026-07-22 and shares the guard cores with pi.
- One dotfiles repo is the source of truth, symlinked into `$HOME` with GNU stow. As of 2026-10-31 it holds 99 pi extensions, 88 shared library files (73 of them `-core.ts` cores) and 91 skills, 77 of them linked into Claude Code. A file in the repo does nothing until stow links it, and `stow-drift` checks that.
- Per-command git approval prompts were replaced by gates. Over 30 days the prompt was answered yes 3,829 times out of 3,833 and caught no leak, so routine git now runs unprompted and leak checks run on the bytes that leave the machine: a pre-push gate and a server-side pre-receive hook.
- The tool-routing rules (about 43 KB) are prepended to every request and decide which tool the model reaches for.
- A survey of the pi package registry on 2026-10-19 (~5,300 packages) produced one trial install. The rest duplicated a subsystem the harness already had or carried far more code than the one idea worth taking.

### Claude Code, one repo at a time (2025-03 to 2026-01)

The first agent was Claude Code, configured per repo. A `CLAUDE.md` landed in `servarr-compose` on 2025-03-29 (`6a3301e`) and in `pastebin` on 2025-04-11 (`0489b5e`, "guidance to Claude Code (claude.ai/code)"). The shell history records the global npm install of Claude Code on 2025-04-26 and interactive `claude` sessions from 2025-06-24. More repos gained one through 2025 (`gloryhole` on 2025-11-21, `redirector` on 2025-12-17). Each file carried that repo's rules, and rules shared across repos, such as "make sure commits are without co-author/claude", were copied from file to file. Nothing was shared, guarded or versioned in one place, so this era left instruction files behind and no harness.

### The opencode era (2026-01 to 2026-05)

opencode was installed on 2026-01-14 (the shell history records the install script at 09:24 UTC; the first of 3,060 opencode sessions started five minutes later). The dotfiles repo gained an opencode configuration on 2026-01-19 (`ae30617`), with MCP servers for Cloudflare docs, mermaid, TypeScript and fetch. Over the following months that grew into a fork of opencode itself, with its own patches and a `FORK.md` describing them (methodology injection among them), synced with upstream by hand.

### The move to pi (2026-05-21) and opencode's retirement (2026-08-15)[^opencode-retired]

The migration to pi started on 2026-05-21: a converter that moved opencode's SQLite sessions into pi's JSONL format (`1641264`), the first pi guard (`git-gh-gate.ts`, `66067f6`), the web research tool (`a6b716d`), and the docs and context7 integrations that closed the remaining gaps (`a670b70`). From then on pi was the harness in daily use and opencode the fallback.

On 2026-08-15 opencode was retired (`c4b39c9`). The `.config/opencode/` tree was deleted from the dotfiles repo, with git history as the archive, and the tool-routing rules moved to `.pi/agent/prompts/tool-routing.md`, prepended to the system prompt by `tool-routing.ts` on every turn.

Claude Code came back as a second harness after five months unused (the shell history has no `claude` launch from 2026-02 to 2026-06). The dotfiles repo wired it to the shared skills and a `CLAUDE.md` on 2026-07-22 (`c92ee94`), and the dual-harness plan of 2026-08-11 (`ff1ea53`) moved it onto the guard cores in `.pi/agent/extensions/lib/`. The port document (`pi-to-claude-code-port.md`, 17 commits through 2026-08-12) maps pi's in-process TypeScript extensions to Claude Code's separate mechanisms: MCP servers for tools, hook scripts for guards, a statusline for TUI state, commands for slash prompts, and subagents for delegation.

#### Guards

The earliest pi extensions were guards: `git-gh-gate.ts` (2026-05-21) and `tool-guard.ts` (2026-05-22). `confidential-write-guard.ts` (2026-06-26) blocks identifiers the user has confirmed are confidential. `epistemic-guard.ts` (2026-08-03) blocks an emitted version, flag, path, URL or CVE id that appears in no tool result of the current session. `ascii-punctuation-guard.ts` and `ai-tell-guard.ts` enforce the prose rules. By 2026-10-20, 18 extensions hooked `tool_call`.

On 2026-10-20 the per-command git approval prompt was replaced by a tiered gate. Routine local or recoverable git (commit, push without force or delete, worktree add and remove, merge, switch) runs unprompted when the global git hooks are active, and every decision is written to an audit log. History rewrites, force and delete pushes, and hook bypasses still prompt. Leak checks moved to a client pre-push gate (gitleaks, blocked terms and sensitive files everywhere; on public targets also an identifier and provenance scan and a local-model review) and a Forgejo pre-receive hook. A daily cache tells every layer which repos are public, and `agent-inventory` lists the worktrees, branches, unpushed commits, stashes and dirty trees agents leave behind.

#### Memory store

`memledger.ts` (2026-08-09) connected pi to a Postgres session store shared across clients, with full-text and vector search, seeded from 640,000 existing messages.[^memledger-640k] `memledger-seed.ts` (2026-08-16) added live ingest on session events. By 2026-10 the store served seven search tools (`memledger_search`, `search_messages`, `semantic_search`, `search_ledger`, `search_memories`, `get_memory`, `list_sessions`) and held the only full copy of sessions older than 30 days, since the local FTS5 index prunes at 30 days.

#### Context and compaction

`tool-output-prune.ts` (2026-05, algorithm ported from the opencode fork) and `tool-output-spill.ts` (2026-08-21) bound oversized tool output. The prune was rewritten on 2026-10-10 to keep the prompt prefix stable: it fires only past a trigger floor, prunes down to a low watermark, never un-prunes a result, records its decisions as `context_edit` entries, and below the floor works on a `structuredClone` so the prefix stays byte-identical for the provider's prompt cache. The `prefix-compaction.ts` trial (2026-10-20) re-sent the last request with one summarise instruction appended so the provider's prefix cache could serve the history. It was slower than pi's default compaction on both providers in use and ships off by default; the [context and prompt-cache reference](/reference/agent-context-and-prompt-cache/) has the numbers.

#### Loops

The self-correcting loop shipped incrementally from 2026-07-13: a sensor-gated inner loop with a governor (wall-clock budgets, cgroup limits, git checkpoint and rollback), a model-escalation ladder and an adversarial review. `loop graph` (2026-10-06, `fa5e895`) added dependency-graph scheduling for multi-loop runs. `garden` (2026-10-13) runs the skills lint and `stow-drift` unattended every Sunday at 06:00.

#### Research stack

A self-hosted research stack grew alongside: SearXNG metasearch, a crawler that escalates from `curl_cffi` to Playwright, OSINT tools, a Singapore rental due-diligence suite, and MCP integration. The tool-routing rules escalate in both directions between it and Exa: when SearXNG returns nothing on a long-tail local query the agent tries Exa, and when Exa returns nothing it falls back to SearXNG.

#### The package survey

On 2026-10-19 the pi.dev package registry listed ~5,300 community packages. The survey read the top 300 by downloads plus 16 that overlapped the harness's own extensions, all via `npm pack` with nothing installed or executed. One was worth a trial (prefix-cache compaction, above).

## Harness layout

The source of truth is one dotfiles repo, symlinked into `$HOME` with GNU stow.

```dot
    mcp_json [label=".pi/agent/mcp.json"];
    claude [label=".claude/\nhooks, MCP toolkit,\n77 skill symlinks"];
    git_hooks [label=".config/git/hooks/\npre-push gate"];
  }

  pi_live [label="pi\n(primary)"];
  cc_live [label="Claude Code\n(second harness)"];
  git [label="git push"];

  ext -> pi_live [label="stow"];
  skills -> pi_live;
  prompts -> pi_live;
  mcp_json -> pi_live;
  lib -> ext [style=dashed, label="imported"];
  lib -> claude [style=dashed, label="imported"];
  lib -> git_hooks [style=dashed, label="imported"];
  claude -> cc_live [label="stow"];
  git_hooks -> git [label="stow"];

```

1. The dotfiles repo holds the extensions, the shared library cores, skills, prompt fragments, MCP server config, the Claude Code adapters and the git hooks.
2. GNU stow symlinks them into `$HOME`. A fresh machine needs `--no-folding`; `.stow-local-ignore` excludes what should not be linked (`.git`, `README.md`, `AGENTS.md`, `package.json`).
3. pi loads every top-level `.pi/agent/extensions/*.ts` and `*/index.ts` at startup. Claude Code reads `.claude/hooks/` and `.claude/mcp/toolkit.ts`, which import the cores from `.pi/agent/extensions/lib/`. The git hooks import the same cores.
4. `stow-drift` exits 1 on a repo file in a loaded tree that has no live symlink. Exit 1 means dead config.

Counts in this section are as of 2026-10-31: 96 top-level `.ts` files plus three directory extensions (`lsp/`, `session-fts/`, `session-ledger/`), 84 top-level skills plus 7 under `skills/work/`.

### Why shared cores

A pi extension registers in one TypeScript file and can define a tool, intercept tool calls, inject context and draw TUI. Claude Code splits the same surface across MCP servers (tools), hook scripts (guards), the statusline (TUI state), commands (slash prompts) and subagents. Each rule's logic lives once, in `lib/<name>-core.ts`, and a thin pi extension and a thin Claude Code hook import it. The git hooks import the same cores for the pre-push gate, so a rule change lands in one file.

### Prompt fragments

Two prose files are added to every request:

- `tool-routing.md`, prepended by `tool-routing.ts`: the search pipeline, web research escalation, the docs.erfi.io workflow, LSP for code intelligence, subagent delegation, memory and session-search triggers, bash discipline and background-task rules. The extension resolves the file relative to its own module path, so a pi-package checkout loaded in place works too.
- `APPEND_SYSTEM.md`, appended: commit and PR authorship (no AI-attribution trailers), safety, epistemic calibration, confidential identifiers in tracked files, output formatting, and AI prose tells.

Both are mirrored by hand into `.claude/CLAUDE.md` for Claude Code. `local-model-rules.md` is added only when a local llama-server model is in use.

### Skills tree

Each skill is a directory under `.pi/agent/skills/` with a `SKILL.md`: frontmatter whose `description` is the trigger text the model sees (capped at 500 characters), and a body capped at 500 lines. `scripts/skills-lint.py` checks frontmatter shape, ASCII punctuation, dead paths, retired terms and freshness (a `metadata.verified` date older than 90 days warns). It runs in the pre-commit hook and in the weekly `garden` run.

Skills reach Claude Code through one symlink per skill in `.claude/skills/`, so that directory's contents are the allowlist ([A skills system for coding agents](/reference/agent-skills-system/)). Skills that touch private session data stay pi-only.

### MCP servers

Since 2026-09-29 pi reads MCP servers from a native `.pi/agent/mcp.json`; before that a separate bridge package did the job. A server is a local `command` or a remote `url`, with OAuth where the server supports it. Secrets go in as `${VAR}` env references or `!command` substitution, never as literal values. Rarely used servers are marked `"exposure": "deferred"` and the model finds their tools through `tool_search`.

A server that only one project needs sits in the global file with `"enabled": false`, and that project's `.pi/mcp.json` carries a bare `{"enabled": true}` override.

### Project trust

Since pi 0.79.0, project-local inputs (`.pi/` and `AGENTS.md` in the working directory) load only after a trust decision. Global config under `~/.pi/agent/` always loads. Decisions persist to `~/.pi/agent/trust.json`, which is runtime state and not tracked. The subagent spawners (`task.ts`, `bg-tasks.ts`) pass `--approve` only when the parent session trusts the working directory, so a subagent never loads project inputs the user declined.

## Where each guard runs

pi fires extension events at fixed points in a turn. Each guard hooks the point where the thing it checks first exists: the prompt before the model sees it, the tool call before it runs, the tool result before the model reads it, the final reply, and the push.

```dot
  end [label="agent_end\nuncarded-guard,\ngit-session-report"];
  run [label="tool runs"];
  result [label="tool_result\nsecret-output (mask),\nuntrusted-content (wrap),\ntool-output-spill"];
  push [label="git pre-push\nleak gate"];

  prompt -> model;
```

The event names are from each extension's `pi.on(...)` registrations. Several guards hook more than one point: `secret-output-guard.ts` blocks reads of registered secret stores at `tool_call` and masks registered values at `tool_result` and `message_end`, and `epistemic-guard.ts` checks writes at `tool_call` and answers at `message_end`.

## Lessons that generalise

Each comes with the incident or measurement behind it.

### A config file is dead until it is linked

On 2026-08-27 a guard extension was written, unit-tested, committed and documented, but never stow-linked. No symlink pointed from `~/.pi/agent/extensions/` to the repo file, so the guard never loaded in the session it was written to protect.

`stow-drift` now exits 1 on a repo file in a loaded tree with no live symlink, and runs before any claim that a config change works. Extensions load at session start, so the check runs in a fresh process instead of waiting for a restart: `timeout -s KILL 120 pi -p --no-mcp '<text that should trip the guard>' </dev/null`.

### A prompt answered yes 99.9% of the time protects nothing

Over 30 days the git approval prompt fired 3,833 times across 205 sessions and was denied 4 times: two misclicks, one change of mind and one "check first". None of the 3,833 stopped a secret or a confidential term from leaving the machine. Each prompt still stopped the session until someone answered it.

The tiered gate lets routine git run and moved leak protection into checks that run on every push: the client pre-push gate and the server pre-receive hook. Skipping either needs a flag (`--no-verify` or a push option) that the tier gate holds for approval. A prompt remains only for irreversible or remote-config actions. [Running agent git commands without per-command approval prompts](/reference/agent-git-without-prompts/) has the baseline and the replay.

### A blocked compound command has to say what did not run

On 2026-07-07 a compound command (write a commit message with a heredoc, then `git add`, `git commit -F`, `git push`) was blocked by one guard whose reason said only "re-run your bash". The agent re-ran the `git commit` suffix alone, which failed because the message file had never been written, and spent four turns on it. When it re-ran the full compound, a second guard blocked it, because pi stops at the first blocking `tool_call` handler and the second guard's once-per-repo notice had never fired.

The block reason now states that no segment of the command ran, heredoc and `git add` included, and that the whole command must be re-run. The guards share one module for that notice and for the once-per-repo nudges, so a re-run is blocked at most once.

### Measure before optimising

`/context` (`context-inspector.ts`) showed that the system prompt changed within a session. Six extensions return a full `systemPrompt` from `before_agent_start`, and the system prompt sits at position 0, so any change to one of those strings misses the provider's prefix cache. A semantic retrieval block was injected on the first qualifying prompt and absent from the next, which changed the prompt at byte offset 40,224 and cost two cache misses per session. A `memory` save mid-session changes the memory block the same way.

The fix moved the one-shot block out of the system prompt and into a message, so the prompt stays byte-identical across the session. The measurement is in the [context and prompt-cache reference](/reference/agent-context-and-prompt-cache/).

### Read third-party packages for ideas, not installs

The 2026-10-19 survey of ~5,300 community pi packages produced one trial. The rest duplicated subsystems the harness already had (subagents, todos, guards, LSP, memory) or carried a much larger surface than the idea worth taking. Reading the top candidates' source with `npm pack`, taking the one technique that improves on what exists, and installing nothing kept the survey free of install-time code execution.

### Routing rules shape every request

`tool-routing.md` is about 43 KB, prepended to every request for every model. Three of its rules and the failure each targets:

- After two search calls with no drill-in, open the most likely hit. Targets the agent rewording the same query instead of reading a result.
- Search session history before asking anyone. Targets questions to the user whose answer `memledger_search` already held.
- Never `curl` a search engine from bash. Targets raw-curl fallbacks when Exa returned nothing, while the self-hosted SearXNG and crawler were available.
