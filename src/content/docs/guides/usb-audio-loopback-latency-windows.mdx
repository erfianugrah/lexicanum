How long does a sound take from a game to my ears through a USB DAC? I wanted a number rather than a forum claim, so this times it with a cable loop: the DAC's output goes into an audio interface, a script plays clicks through the DAC the way most games play audio, and it timestamps when each click comes back in. My D70 comes out at 43.0-47.9 ms from the app to the DAC's output, 12 ms of which is Windows' own queue. The recording side is part of every loop, so on its own a loop only gives an upper bound, but reading the output driver's clock as well lets you bound the recorder's share, which is how the range comes out.

You'll need Windows PowerShell 5.1 (no admin), an audio interface with a line or mic input, a cable from the output under test into that input, and the script below. Everything was measured on one machine on 2026-10-26.

## Constants

### The rig

| Piece | Detail |
|---|---|
| OS | Windows 10 22H2 (build 19045) |
| DAC | Topping D70 Pro Sabre, Microsoft USB Audio 2.0 class driver (`usbaudio2`, 10.0.19041.7802), into a Topping A70 Pro over XLR |
| Interface (the recorder) | Solid State Logic SSL 2, Thesycon driver (`SSLUSBDriverks`, 5.72.3.28145) |
| Other output | Monitor audio over the GPU (NVIDIA High Definition Audio, PCIe) |
| USB | DAC and interface on the chipset's USB controller |
| Format | 48 kHz, 32-bit float, WASAPI shared mode |

### What Windows reports per output

Read with `IAudioClient::GetDevicePeriod` and `IAudioClient3::GetSharedModeEnginePeriod`[^ms-engineperiod], no cable needed:

| Output | Engine period default | Engine period minimum |
|---|---|---|
| D70 Pro Sabre (`usbaudio2`) | 10 ms | 7 ms |
| SSL 2 Output 1/2 (Thesycon) | 10 ms | 10 ms |
| Monitor (NVIDIA HDA) | 10 ms | 10 ms |

Microsoft's low-latency audio page[^ms-lowlatency] says Windows 10 apps in shared mode get 10 ms buffers by default, smaller ones only if the app asks (AudioGraph or `IAudioClient3`) and the driver supports them, and that the inbox HD Audio driver goes down to 128 samples, which is 2.67 ms at 48 kHz. So an onboard HD Audio codec can run smaller buffers than either USB device here, but only for apps that ask.

### What one measurement includes

The script stamps the time right after it hands a buffer with a click to Windows (`ReleaseBuffer`), and the capture side stamps each recorded packet with the QPC time the driver reports (`IAudioCaptureClient::GetBuffer`, "converted to 100-nanosecond units"[^ms-getbuffer]). The difference covers Windows' queue ahead of the click, the audio engine, the output driver and device, the cable, and the recording path up to that timestamp. The recording path is the same for every output measured through the same input, so it cancels out of a comparison but not out of an absolute number.

Text version: the script writes a click into a shared-mode buffer and notes the time, Windows mixes it and sends it over USB to the DAC, the DAC's analog output goes down a cable into the interface, and the interface sends the recording back over USB with a timestamp per packet. The script finds the click's first sample in the recording and subtracts.

## Part 1: cable the loop

1. Run a cable from the output you want to measure into an interface input. For my D70 that was one of its XLR outputs (the left one that normally feeds the A70) into SSL 2 Input 1. One channel is enough, the script plays the click on both.
2. Turn the input gain near minimum and the DAC volume low (about 20 % in Windows). A line output into a mic preamp is hot, and the script only needs a clear click.
3. A stereo headphone jack into a balanced TRS input needs care: the input records tip minus ring, so identical left and right cancel to almost nothing. Play the click on the left channel only (`-LeftOnly`).
4. Check the input is live before blaming the script: pull the cable out of the output end and touch the plug's tip with your finger, the hum should light the input's signal LED. On my SSL 2 the jack input took the headphone signal with LINE pressed. Earlier in the day I thought it needed LINE released, but that was with the output muted and the volume at 10 %, so don't trust that one.
5. Check the output isn't muted in Windows. Mine was, which hid everything else for a while.

## Part 2: the script

Save as `audio-loopback.ps1`. It opens the output in shared mode, event-driven, at the default engine period, plays bursts of 2 kHz for 2 ms each, a quarter second apart, and prints each click's latency and the median. It also reads the render stream's `IAudioClock`, whose device position is "the sample that is currently playing through the speakers" with the QPC time it was read[^ms-clock], and interpolates when each click was reported playing. That splits every click into the part up to where the output driver says it's playing and the part after.

```powershell
# audio-loopback.ps1 - output latency as a game sees it, measured through a cable loop.
#
#   .\audio-loopback.ps1 -Render 'D70' -Capture 'Input 1 (SSL 2' [-Clicks 25] [-Amplitude 0.25]
#   .\audio-loopback.ps1 -List
#   -LeftOnly: burst on the left channel only. Needed when a stereo headphone jack feeds a balanced
#   TRS input: identical L and R on tip and ring cancel to almost nothing (tip minus ring).
#
# Cable the output under test into the capture input. The script opens the output in WASAPI
# shared mode, event-driven, at the engine's default period (how most games play audio), plays
# short 2 kHz bursts, and timestamps when each comes back on the capture input.
#
# Latency = capture time of the burst's first sample (IAudioCaptureClient::GetBuffer QPC position,
#           "converted to 100-nanosecond units", https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer)
#         - QPC time right after the app released the buffer holding the burst.
# It includes the capture side's own delay (if its driver timestamps late), which is the same
# for every output measured through the same input: compare outputs, do not read one number as
# the output's absolute latency. Interface IDs from Wine's audioclient.idl, flags from
# https://learn.microsoft.com/en-us/windows/win32/coreaudio/audclnt-streamflags-xxx-constants
param(
    [string] $Render,
    [string] $Capture = 'Input 1 (SSL 2',
    [int] $Clicks = 25,
    [double] $Amplitude = 0.25,
    [switch] $LeftOnly,
    [switch] $List
)
$ErrorActionPreference = 'Stop'
Add-Type -TypeDefinition @'

public class Endpoint { public string Id; public int Flow; }
public static class Loop {
  static void Ck(int hr, string what) { if (hr != 0) throw new Exception(what + " failed: 0x" + hr.ToString("X8")); }
  public static List<Endpoint> Endpoints() {
    var r = new List<Endpoint>(); var e = (IMMDeviceEnumerator)new MMDeviceEnumeratorCo();
    for (int flow = 0; flow < 2; flow++) {
      IMMDeviceCollection c; Ck(e.EnumAudioEndpoints(flow, 1, out c), "EnumAudioEndpoints"); uint n; c.GetCount(out n);
      for (uint i = 0; i < n; i++) { IMMDevice d; c.Item(i, out d); string id; d.GetId(out id); r.Add(new Endpoint { Id = id, Flow = flow }); }
    }
    return r;
  }
  static IAudioClient Open(string id, int flow) {
    var e = (IMMDeviceEnumerator)new MMDeviceEnumeratorCo(); IMMDeviceCollection c; e.EnumAudioEndpoints(flow, 1, out c);
    uint n; c.GetCount(out n); Guid iid = typeof(IAudioClient).GUID;
    for (uint i = 0; i < n; i++) {
      IMMDevice d; c.Item(i, out d); string did; d.GetId(out did);
      if (did == id) { object o; Ck(d.Activate(ref iid, 23, IntPtr.Zero, out o), "Activate"); return (IAudioClient)o; }
    }
    throw new Exception("endpoint not found: " + id);
  }
  static long Now() { return (long)(Stopwatch.GetTimestamp() * (10000000.0 / Stopwatch.Frequency)); } // 100 ns units, same base as the capture QPC position
  static void CheckFloat(IntPtr fmt, out int ch, out int rate) {
    ch = Marshal.ReadInt16(fmt, 2); rate = Marshal.ReadInt32(fmt, 4); int bits = Marshal.ReadInt16(fmt, 14);
    if (bits != 32) throw new Exception("mix format is " + bits + "-bit, expected 32-bit float");
  }

  public static string[] Run(string renderId, string captureId, int clicks, double amp, bool leftOnly) {
    var log = new List<string>();
    // capture: shared mode, polled, 200 ms buffer
    var cap = Open(captureId, 1); IntPtr cfmt; cap.GetMixFormat(out cfmt); int cch, crate; CheckFloat(cfmt, out cch, out crate);
    Ck(cap.Initialize(0, 0, 2000000, 0, cfmt, IntPtr.Zero), "capture Initialize");
    Guid ccid = typeof(IAudioCaptureClient).GUID; object co; Ck(cap.GetService(ref ccid, out co), "capture GetService"); var cc = (IAudioCaptureClient)co;
    var samples = new List<float>(); var times = new List<long>(); // per frame: max |sample| across channels, and its time
    bool stop = false; Exception capErr = null; int pkts = 0, silentPkts = 0;
    var th = new Thread(() => {
      try {
        while (!stop) {
          uint next; cc.GetNextPacketSize(out next);
          while (next > 0) {
            IntPtr data; uint frames, flags; ulong dpos, qpc; Ck(cc.GetBuffer(out data, out frames, out flags, out dpos, out qpc), "capture GetBuffer");
            var buf = new float[frames * cch]; if ((flags & 2) == 0) Marshal.Copy(data, buf, 0, buf.Length); else silentPkts++; // 2 = AUDCLNT_BUFFERFLAGS_SILENT
            pkts++;
            for (int f = 0; f < frames; f++) {
              float m = 0; for (int k = 0; k < cch; k++) m = Math.Max(m, Math.Abs(buf[f * cch + k]));
              samples.Add(m); times.Add((long)qpc + (long)(f * 10000000.0 / crate));
            }
            cc.ReleaseBuffer(frames); cc.GetNextPacketSize(out next);
          }
          Thread.Sleep(1);
        }
      } catch (Exception ex) { capErr = ex; }
    });
    // render: shared mode, event-driven, default engine period (buffer duration 0)
    var ren = Open(renderId, 0); IntPtr rfmt; ren.GetMixFormat(out rfmt); int rch, rrate; CheckFloat(rfmt, out rch, out rrate);
    Ck(ren.Initialize(0, 0x00040000, 0, 0, rfmt, IntPtr.Zero), "render Initialize");
    var ev = new AutoResetEvent(false); Ck(ren.SetEventHandle(ev.SafeWaitHandle.DangerousGetHandle()), "SetEventHandle");
    uint bufFrames; ren.GetBufferSize(out bufFrames); long lat; ren.GetStreamLatency(out lat); long dp, mp; ren.GetDevicePeriod(out dp, out mp);
    log.Add(string.Format("render buffer {0} frames ({1:F2} ms) at {2} Hz, {3} ch; GetStreamLatency {4:F2} ms; device period {5:F2} ms",
      bufFrames, bufFrames * 1000.0 / rrate, rrate, rch, lat / 1e4, dp / 1e4));
    Guid rcid = typeof(IAudioRenderClient).GUID; object ro; Ck(ren.GetService(ref rcid, out ro), "render GetService"); var rc = (IAudioRenderClient)ro;
    // IAudioClock: device position = "the sample that is currently playing through the speakers", with its QPC time
    // (https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclock-getposition)
    Guid ckid = typeof(IAudioClock).GUID; object cko; Ck(ren.GetService(ref ckid, out cko), "render clock"); var clk = (IAudioClock)cko;
    ulong cfreq; clk.GetFrequency(out cfreq);
    var clkFrames = new List<double>(); var clkQpc = new List<long>(); var clickFrames = new List<long>(); long written = bufFrames;
    int burst = rrate / 500; // 2 ms
    var writes = new List<long>(); var pads = new List<uint>();
    IntPtr p0; Ck(rc.GetBuffer(bufFrames, out p0), "prefill"); rc.ReleaseBuffer(bufFrames, 2); // 2 = AUDCLNT_BUFFERFLAGS_SILENT
    th.Start(); Thread.Sleep(300);
    Ck(cap.Start(), "capture Start"); Ck(ren.Start(), "render Start");
    long t0 = Now(), every = 2500000, warm = 10000000; int sent = 0; long nextAt = t0 + warm;
    while (sent < clicks) {
      ev.WaitOne(200);
      { ulong cp, cq; if (clk.GetPosition(out cp, out cq) == 0) { clkFrames.Add(cp * (double)rrate / cfreq); clkQpc.Add((long)cq); } }
      uint pad; ren.GetCurrentPadding(out pad); uint avail = bufFrames - pad; if (avail == 0) continue;
      IntPtr data; Ck(rc.GetBuffer(avail, out data), "render GetBuffer");
      var buf = new float[avail * rch];
      bool click = Now() >= nextAt;
      if (click) for (int f = 0; f < Math.Min(burst, (int)avail); f++) {
        float v = (float)(amp * Math.Sin(2 * Math.PI * 2000 * f / rrate)); for (int k = 0; k < (leftOnly ? 1 : rch); k++) buf[f * rch + k] = v; }
      Marshal.Copy(buf, 0, data, buf.Length); rc.ReleaseBuffer(avail, 0);
      if (click) { writes.Add(Now()); pads.Add(pad); clickFrames.Add(written); sent++; nextAt += every; }
      written += avail;
    }
    var tail = Stopwatch.StartNew();
    while (tail.ElapsedMilliseconds < 500) { ulong cp, cq; if (clk.GetPosition(out cp, out cq) == 0) { clkFrames.Add(cp * (double)rrate / cfreq); clkQpc.Add((long)cq); } Thread.Sleep(2); }
    ren.Stop(); cap.Stop(); stop = true; th.Join();
    if (capErr != null) throw capErr;
    // onsets: first frame above 25 % of the run's peak, 150 ms refractory
    float peak = 0; foreach (var s in samples) peak = Math.Max(peak, s);
    log.Add(string.Format("capture {0} frames at {1} Hz, {2} ch, peak {3:F6}, {4} packets ({5} flagged silent)", samples.Count, crate, cch, peak, pkts, silentPkts));
    if (peak < 0.002) { log.Add("no signal on the capture input: check the cable, the input gain and the output volume"); return log.ToArray(); }
    var onsets = new List<long>(); float thr = peak * 0.25f; long last = 0; bool any = false;
    for (int i = 0; i < samples.Count; i++) if (samples[i] >= thr && (!any || times[i] - last > 1500000)) { onsets.Add(times[i]); last = times[i]; any = true; }
    var lats = new List<double>(); var winPart = new List<double>(); var hwPart = new List<double>();
    for (int i = 0; i < writes.Count; i++) {
      long w = writes[i]; long hit = -1; foreach (var o in onsets) if (o > w - 50000 && o < w + 2000000) { hit = o; break; } // -5 ms .. +200 ms
      if (hit < 0) { log.Add(string.Format("click {0,2}: not found", i + 1)); continue; }
      double ms = (hit - w) / 1e4; lats.Add(ms);
      // when did the render clock reach the click's first frame? interpolate between clock readings
      double dev = double.NaN; long cf = clickFrames[i];
      for (int k = 1; k < clkFrames.Count; k++) if (clkFrames[k - 1] < cf && clkFrames[k] >= cf && clkFrames[k] > clkFrames[k - 1]) {
        dev = clkQpc[k - 1] + (clkQpc[k] - clkQpc[k - 1]) * (cf - clkFrames[k - 1]) / (clkFrames[k] - clkFrames[k - 1]); break; }
      string split = "";
      if (!double.IsNaN(dev)) { double a = (dev - w) / 1e4, b = (hit - dev) / 1e4; winPart.Add(a); hwPart.Add(b); split = string.Format("  = {0,6:F2} until the driver reports it playing + {1,6:F2} after", a, b); }
      log.Add(string.Format("click {0,2}: {1,7:F2} ms  (queued behind {2} frames = {3:F2} ms){4}", i + 1, ms, pads[i], pads[i] * 1000.0 / rrate, split));
    }
    if (lats.Count > 0) {
      lats.Sort(); double sum = 0; foreach (var x in lats) sum += x;
      log.Add(string.Format("RESULT {0}/{1} clicks: median {2:F2} ms, min {3:F2}, max {4:F2}, mean {5:F2}",
        lats.Count, writes.Count, lats[lats.Count / 2], lats[0], lats[lats.Count - 1], sum / lats.Count));
      log.Add(string.Format("        p25 {0:F2} ms, p75 {1:F2} ms", lats[lats.Count / 4], lats[lats.Count * 3 / 4]));
    }
    if (winPart.Count > 0) {
      winPart.Sort(); hwPart.Sort();
      log.Add(string.Format("SPLIT   app -> render driver reports it playing: median {0:F2} ms; that -> captured: median {1:F2} ms ({2} clicks, render clock {3} Hz)",
        winPart[winPart.Count / 2], hwPart[hwPart.Count / 2], winPart.Count, cfreq));
    } else log.Add("SPLIT   render clock gave no usable readings");
    log.Add(string.Format("onsets detected: {0}", onsets.Count));
    return log.ToArray();
  }
}

function Get-Name($id) { (Get-PnpDevice -InstanceId "SWD\MMDEVAPI\$id" -ErrorAction SilentlyContinue).FriendlyName }
```

```powershell
.\audio-loopback.ps1 -List                                    # endpoint names
.\audio-loopback.ps1 -Render 'D70' -Capture 'Input 2 (SSL 2' -Clicks 50
.\audio-loopback.ps1 -Render 'SSL 2' -Capture 'Input 1 (SSL 2' -LeftOnly -Clicks 50
```

`-Render` and `-Capture` match on the endpoint name and have to match exactly one endpoint each. If it says there's no signal, check the cable, the gain and the Windows volume, the script prints the capture peak so you can see how far off it is (below 0.002 counts as no signal; the noise floor here was about 0.0001).

## Part 3: measure the outputs

Run the outputs back to back so the comparison holds. My runs, 50 clicks each, 48 kHz, default shared-mode period, one session (2026-10-26, about 17:00):

| Loop | Total (median, p25-p75) | App -> driver says playing | -> captured |
|---|---|---|---|
| D70 XLR -> SSL 2 Input 2 | 47.88 ms (47.57-48.10) | 42.97 ms | 4.83 ms |
| SSL 2 headphone -> SSL 2 Input 1 (`-LeftOnly`) | 51.32 ms (51.30-51.33) | 31.97 ms | 19.35 ms |
| SSL 2 driver loopback (no analog) | 50.26 ms (50.23-50.27) | 31.97 ms | 18.29 ms |

The first runs, earlier the same day and hours apart, 25 clicks each: D70 XLR -> SSL 2 Input 1 47.33 ms (47.16-47.54, one at 38.56), SSL 2 headphone -> SSL 2 Input 1 51.51 ms (50.09-51.61, one at 42.22). Those put the D70 about 4.2 ms ahead of the SSL 2's output, with the D70 path at 47.3 ms and 12 ms of it the queue; the single low readings were most likely the script stamping `ReleaseBuffer` late. Within that D70 run the readings crept up about 0.4 ms, the clock drift again.

In every run Windows gave the stream a 1056-frame buffer (22 ms) and each click sat behind 576 frames (12 ms) already queued. `GetStreamLatency` came back 0, so neither driver tells Windows about its own delay. A D70 run earlier that day gave 47.33 ms. The D70's wider p25-p75 is the DAC's and the interface's clocks drifting against each other; the SSL 2 loops share one clock.

### The SSL 2's buffer setting

All of the above was with the SSL 2 control panel at 512 samples. At 64 samples, 50 clicks each:

| Loop | 512 samples | 64 samples | -> captured at 64 |
|---|---|---|---|
| SSL 2 driver loopback | 50.26 ms | 39.35 ms | 7.38 ms |
| SSL 2 headphone -> Input 1 | 51.32 ms | 40.70 ms | 8.73 ms |
| D70 XLR -> SSL 2 Input 2 | 47.88 ms | 47.47 ms | 4.57 ms |

So the setting isn't ASIO-only, it applies to the shared-mode path too, but only on the SSL 2's output side: its loops dropped 10.6-10.9 ms, all of it after the driver says playing. The D70 loop goes through the same SSL 2 input and didn't move, so the capture side didn't change.

### The DAC's driver

The D70 also has a vendor driver (Topping V6.16.0, built on Thesycon's), which I'd removed in August because of intermittent crackle. Reinstalled for this, Windows restarted with the DAC left plugged in, both buffers at 128 samples, same cables, 50 clicks each:

| Loop | D70 on Microsoft's `usbaudio2` | D70 on the Topping driver |
|---|---|---|
| D70 XLR -> SSL 2 Input 2 | 47.73 ms (47.47-47.93) | 41.35 ms (41.06-41.63) |
| SSL 2 headphone -> Input 1 (control) | 38.96 ms | 39.58 ms |
| SSL 2 driver loopback (control) | 38.09 ms | 38.11 ms |

The SSL 2 loops didn't move, so the 6.4 ms is the D70's driver. The Topping run had a wider spread, one click at 51.45 ms. Whether the crackle comes back is the real question for that driver, and that's a listening test, not this one.

## Reading the numbers

The last column is "output delay the driver doesn't report" plus "the recorder's capture delay". Both real loops went through the same SSL 2, so the capture delay is the same in both. For the D70 the sum is 4.83 ms. A DAC can only add delay after its driver says a sample is playing, never take it away, so the SSL 2's capture side is at most 4.83 ms. That bounds both outputs:

| Output | App to analog out | Of which Windows' queue |
|---|---|---|
| D70 Pro Sabre (`usbaudio2`) | 43.0-47.9 ms | 12 ms |
| SSL 2 (Thesycon), 512-sample buffer | 46.5-51.3 ms | 12 ms |
| SSL 2 (Thesycon), 64-sample buffer | 36.1-40.7 ms | 12 ms |
| D70 again, SSL 2 at 64 | 42.9-47.5 ms | 12 ms |
| D70 on the Topping driver, 128 samples | 36.6-41.4 ms | 12 ms |

Two more things fall out:

- The SSL 2's analog loop is only 1.06 ms longer than its driver-internal loopback, so its converters and the cable are about 1 ms. Its driver reports samples playing at least 14.5 ms before they leave the jack (19.35 minus at most 4.83).
- The "driver says playing" column means different things per driver (43 ms for usbaudio2, 32 ms for the Thesycon driver), so don't compare that column across drivers, only the totals and the bounds.

There's a claim going round that onboard (PCH) HD Audio is about 35 ms faster than any USB DAC. These numbers don't confirm or rule that out. The HD Audio driver's smaller minimum buffer (2.67 ms against 7-10 ms here) explains a few ms for apps that ask for small buffers. Of the D70's 43-48 ms, 12 ms is the shared-mode queue every output pays, which leaves 31-36 ms for the engine, usbaudio2 and the DAC, and only a non-USB output measured the same way can say how much of that onboard audio would save. A 35 ms gap would need the USB driver and DAC to account for around 30 ms of those 31-36 ms on their own. A browser round-trip test (speaker out to mic in through the browser's own audio stack) isn't comparable: it includes the input device and the browser's buffering, which change when you swap the DAC.

| Check | How | Expected |
|---|---|---|
| Input is live | tap the cable tip, watch the input LED | it flickers |
| Output not muted | Windows sound settings, or the script's peak | peak well above 0.002 |
| Clicks found | `RESULT n/25` line | 25/25 |
| Stable path | spread of the per-click lines | within about 0.5 ms apart from single outliers |

## Gotchas and lessons learned

- The recorder is part of every number. Compare outputs through the same input, don't quote one loop as an output's latency.
- A driver's software loopback endpoint isn't a hardware loop. The SSL 2's `Loopback 1 L/R` measured about 50 ms, but that signal never leaves the driver, so it says nothing about the analog path.
- Stereo into balanced cancels. Identical left and right into a TRS balanced input record as near silence; play one channel.
- Check Windows mute and the interface's input mode before anything else. I lost most of an afternoon to a muted output and a pressed LINE button.
- Run the outputs you compare back to back. My first D70 and SSL 2 runs were hours apart; the table above is from one session.
- Check the interface's own buffer setting. The SSL 2 at 512 samples cost about 11 ms on its output against 64, in shared mode, not just ASIO.
- Don't clip the input. My D70 run hit full scale (peak 1.0) at 100 % Windows volume into the mic preamp. The onset is the first sample over 25 % of the peak, so it moves by at most part of a 2 kHz cycle, but turn it down.
- A browser doesn't necessarily get a smaller buffer than a game. Opening the stream with `IAudioClient3::InitializeSharedAudioStream` at the minimum period (what Chromium does) changed nothing here: the Topping driver, the SSL 2 and NVIDIA's HD Audio driver each offer exactly one period, 480 frames (10 ms). Check what your drivers offer with `GetSharedModeEnginePeriod` before comparing against browser round-trip tests, where onboard HD Audio on Microsoft's driver can get 128 frames.
- Exclusive mode isn't measured here; few games use it.
