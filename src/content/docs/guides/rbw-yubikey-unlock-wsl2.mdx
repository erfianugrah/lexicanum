title: Unlocking rbw with a YubiKey touch on WSL2
description: "Replace the typed rbw master password with a touch on a YubiKey, on an Arch WSL2 box. The master password is age-encrypted to a P-256 key in the YubiKey's PIV applet (age-plugin-yubikey, PIN policy never, touch policy always), and a small pinentry wrapper answers rbw's first-try master-password prompt by decrypting it, while retries, other prompts and every failure go to the normal dialog. Covers getting the key into WSL with usbipd-win, the polkit rule pcscd needs when there is no active session, routing gpg through pcscd, the firmware 5.7 management-key incompatibility, and a Windows toast that asks for the touch."
author: "Erfi Anugrah"
category: secrets
---

`rbw unlock` asks for the Vaultwarden master password every time the agent locks. This guide moves that password onto a YubiKey: it is stored age-encrypted to a key that never leaves the YubiKey's PIV applet, and rbw's pinentry is replaced by a wrapper that decrypts it when rbw asks. Unlocking becomes a touch on the key, prompted by a Windows notification. Typing the password still works, and is what you get whenever the key is missing or not touched in time.

Why rbw is the command-line client in the first place is in [choosing a secrets backend](/reference/choosing-a-secrets-backend/); what reads through the unlocked agent afterwards (`sx`, the digest guard) is in [keeping credentials out of coding-agent transcripts](/reference/agent-secret-guard/). This is the same WSL2 box as [keeping /run/user alive across Docker Desktop stops](/guides/wsl2-run-user-docker-desktop/), whose repair step ends in `rbw unlock`.

Prerequisites: an Arch WSL2 distro with systemd, rbw already logged in and working with a GUI pinentry (`pinentry-gtk` under WSLg), a YubiKey 5 with an unused PIV applet, and admin rights on the Windows host for one install and one bind. Everything here was done and measured on 2026-10-28 on the rig below.

## Constants (read this first)

### The rig

| Piece | Detail |
|---|---|
| Windows host | Windows 10 22H2, build 19045 |
| WSL kernel | `6.18.54.1-microsoft-standard-WSL2`, built with `CONFIG_USBIP_VHCI_HCD=m` |
| Distro | Arch Linux, systemd as PID 1 |
| YubiKey | YubiKey 5 NFC, firmware 5.7.1, USB id `1050:0407` (OTP+FIDO+CCID) |
| rbw | 1.15.0 (a patched build; the pinentry protocol below is upstream's) |

### What the setup depends on

| Fact | Consequence |
|---|---|
| WSL has no USB passthrough of its own | The key reaches Linux over USB/IP: usbipd-win on Windows, the kernel's `vhci_hcd` in WSL. While attached, Windows cannot use the key. |
| pcsc-lite's polkit policy authorises clients by session, and a WSL shell never has an active local session | pcscd rejects every client, so ykman reports `PC/SC not available` with the key attached. A polkit rule for the one user fixes it (Part 2). |
| gpg's scdaemon has its own CCID driver | It cannot reach the key that pcscd serves: `gpg --card-status` says `No such device` while `ykman list` works. `disable-ccid` sends it through pcscd (Part 3). |
| rbw-agent daemonises with no controlling terminal | Nothing can prompt on a terminal from inside its pinentry, so the YubiKey key must decrypt without a PIN: PIN policy `never`, touch policy `always`. The touch is the consent. |
| rbw writes `SETTITLE`, `SETPROMPT`, `SETDESC`, an optional `SETERROR`, then `GETPIN`, closes stdin, and reads one `OK` per command plus a `D` line[^rbw-pinentry] | A pinentry replacement can be a short script that never speaks the full Assuan protocol. |
| A wrong password makes rbw re-prompt with `SETERROR ... (attempt N/3)`, three attempts in all[^rbw-actions] | The wrapper answers only when `SETERROR` is absent, so a stale encrypted file costs one attempt and the dialog handles the rest. |
| Firmware 5.7 ships an AES192 default PIV management key; age-plugin-yubikey 0.5.1 handles only TDES or a PIN-protected key | Key generation fails until the management key is replaced (Part 4). |

## Architecture

```dot

  subgraph cluster_win { label="Windows host"; yk [label="YubiKey\nPIV slot 82: P-256\nPIN never, touch always"]; usbipd [label="usbipd-win"]; toast [label="toast\n(WinRT)"]; }
  subgraph cluster_wsl { label="WSL2 (Arch)";
    vhci [label="vhci_hcd"]; pcscd [label="pcscd\n+ polkit rule"]; plugin [label="age-plugin-yubikey"];
    age [label="age -d"]; wrap [label="pinentry-rbw"]; agent [label="rbw-agent"]; gtk [label="pinentry-gtk"];
    file [label="master.age\n+ identity stub"];
  }
  yk -> usbipd [label="USB"]; usbipd -> vhci [label="USB/IP"]; vhci -> pcscd -> plugin [dir=back, label="APDUs"];
  agent -> wrap [label="GETPIN"]; wrap -> age; age -> plugin; file -> age;
  wrap -> gtk [label="retry, other prompt,\nany failure"]; wrap -> toast [label="powershell.exe"];
}
```

1. rbw-agent starts the configured pinentry, `pinentry-rbw`, and sends its commands.
2. On a first-try `Master Password` prompt the wrapper shows a Windows toast and runs `age -d` on `master.age` with the identity stub.
3. age hands the stub to age-plugin-yubikey, which asks the YubiKey (through pcscd, the USB/IP link and usbipd-win) to do the key agreement. The key waits for a touch.
4. The decrypted password goes back to rbw-agent on stdout. Anything else - a retry, a 2FA prompt, a missing file, no touch within 30 s - goes to `pinentry-gtk`, with the reason added to the dialog text.

## Part 1: attach the YubiKey to WSL

Install usbipd-win on Windows (one UAC prompt) and find the key, Yubico vendor id `1050`:

```powershell
winget install --exact --id dorssel.usbipd-win
usbipd list        # BUSID  VID:PID    DEVICE ... 1050:0407  USB Input Device, Microsoft Usbccid Smartcard Reader (WUDF)
```

Binding shares the device and persists across reboots; it needs an elevated shell once. Attaching does not, and has to be repeated after every reboot and every replug:

```powershell
usbipd bind --busid <busid>           # elevated, once
usbipd attach --wsl --busid <busid>   # each session
usbipd detach --busid <busid>         # hand it back to Windows
```

From inside WSL the same commands run as `"/mnt/c/Program Files/usbipd-win/usbipd.exe"` (the installer's directory is not on the WSL `PATH` until Windows hands WSL a fresh environment). After the attach the kernel sees the key:

```bash
cat /sys/bus/usb/devices/1-1/idVendor /sys/bus/usb/devices/1-1/product
# 1050
# YubiKey OTP+FIDO+CCID
```

`lsusb` needs `usbutils`, which a minimal Arch install does not have; the sysfs read needs nothing.

## Part 2: let your user talk to pcscd

```bash
sudo pacman -S --needed pcsclite ccid yubikey-manager
sudo systemctl enable --now pcscd.socket
ykman list
# WARNING: PC/SC not available. Smart card (CCID) protocols will not function.
# ERROR: Unable to list devices for connection
```

pcscd is running and the key is attached; the journal names the refusal:

```bash
journalctl -u pcscd --since -5min
# pcscd[...]: auth.c:166:IsClientAuthorized() Process 332763 (user: 1000) is NOT authorized for action: access_pcsc
# pcscd[...]: winscard_svc.c:361:ContextThread() Rejected unauthorized PC/SC client
```

Allow the one desktop user both pcsc-lite actions, and nothing else:

```js
// /etc/polkit-1/rules.d/49-pcscd-wsl.rules
// WSL2 has no active local session, so pcsc-lite's default polkit policy
// rejects every client. Allow the desktop user only.
polkit.addRule(function(action, subject) {
    if ((action.id == "org.debian.pcsc-lite.access_pcsc" ||
         action.id == "org.debian.pcsc-lite.access_card") &&
        subject.user == "<user>") {
        return polkit.Result.YES;
    }
});
```

```bash
sudo chmod 644 /etc/polkit-1/rules.d/49-pcscd-wsl.rules
sudo systemctl restart polkit pcscd
ykman list
# YubiKey 5 NFC (5.7.1) [OTP+FIDO+CCID] Serial: <serial>
```

## Part 3: route gpg through pcscd

With ykman working, gpg still does not see the card:

```bash
gpg --card-status
# gpg: selecting card failed: No such device
```

scdaemon tries its built-in CCID driver first. Turn it off so it uses pcscd like everything else:

```bash
echo disable-ccid >> ~/.gnupg/scdaemon.conf
gpgconf --kill scdaemon
gpg --card-status | grep -E 'Reader|Serial'
# Reader ...........: Yubico YubiKey OTP FIDO CCID 00 00
# Serial number ....: <serial>
```

On this box scdaemon and age-plugin-yubikey share the card: `age-plugin-yubikey --list` answered with scdaemon running and again after `gpgconf --kill scdaemon`. Nothing in this setup needs gpg to touch the card - gpg's passphrase is seeded from rbw once rbw is unlocked - but a gpg that cannot see an attached card is a trap the next time something does.

## Part 4: create the age key on the PIV applet

Two things block the plugin on a factory-fresh firmware 5.7 key. First, check what you have:

```bash
ykman piv info
# PIN tries remaining:      3/3
# Management key algorithm: AES192
# WARNING: Using default PIN!
# WARNING: Using default PUK!
# WARNING: Using default Management key!
```

age-plugin-yubikey changes a default PIN itself during generation and sets the PUK to the same value. The PIV PIN is 6 to 8 characters, as the plugin's own prompt says; typing a longer one at its "Enter PIN" prompt fails with `Error while communicating with YubiKey: size error`, and the retry counter stays at 3/3 because nothing reached the card. At that first prompt it wants the current PIN, `123456` on a fresh key, and asks for the new one afterwards.

The management key is the second blocker. Generation with the AES192 default fails with:

```
Error: Custom unprotected non-TDES management keys are not supported.
You can use the YubiKey Manager CLI to change to a protected management key:
  ykman piv access change-management-key -a TDES --protect
```

Do what it says. `--protect` generates a random TDES key and stores it on the YubiKey behind the PIN; press Enter for the current (default) key and give the PIN:

```bash
ykman piv access change-management-key -a tdes --protect
# Enter the current management key [blank to use default key]:
# Enter PIN:
# New management key set.
```

Now generate the key in PIV slot 1 (retired slot 82) and save the identity stub, which only tells age which YubiKey and slot to ask and is not secret:

```bash
umask 077
age-plugin-yubikey --generate --serial <serial> --slot 1 --name rbw-unlock \
  --pin-policy never --touch-policy always > ~/.config/rbw/yubikey-identity.txt
grep -o 'age1yubikey1[0-9a-z]*' ~/.config/rbw/yubikey-identity.txt   # the recipient
```

Run this in an ordinary terminal. The plugin's interactive PIN dialog misbehaved inside a coding agent's pseudo-terminal wrapper here: one run exited 130 at the "Repeat the PIN/PUK" prompt (the PIN change had gone through anyway), the next printed nothing at all.

```bash
ykman piv info | sed -n '/Slot 82/,/Fingerprint/p'
# Slot 82 (RETIRED1):
#   Private key type: ECCP256
#   Subject DN:       CN=rbw-unlock,OU=0.5.1,O=age-plugin-yubikey
```

## Part 5: encrypt the master password

Read the password without echo, encrypt it without a trailing newline, and check the round trip before trusting it (one touch):

```bash
umask 077
d=~/.config/rbw
recip=$(grep -o 'age1yubikey1[0-9a-z]*' "$d/yubikey-identity.txt" | head -1)
read -rsp 'rbw master password: ' pw; echo
printf '%s' "$pw" | age -r "$recip" -o "$d/master.age"
[ "$(age -d -i "$d/yubikey-identity.txt" "$d/master.age")" = "$pw" ] && echo "roundtrip ok"
unset pw
```

The password exists only in the shell variable and the pipe. A changed master password later needs only this part again.

## Part 6: the pinentry wrapper

The wrapper reads rbw's commands, decides, and either answers or hands the same commands to the real pinentry. It answers only a first-try `Master Password` prompt; 2FA codes, the API key prompts and retries keep the normal dialog. Every failure path adds its reason to the dialog's description, so a missing key shows up as "YubiKey decrypt failed" or "timed out after 30s waiting for the touch" in the box you then type into.

Save it as `~/.local/bin/pinentry-rbw` and make it executable:

```python
#!/usr/bin/env python3
# pinentry-rbw: answer rbw's first-try master-password prompt from a
# YubiKey-bound age file; relay everything else to the real pinentry.
import os, shlex, shutil, signal, subprocess, sys

REAL = os.environ.get("PINENTRY_RBW_REAL") or shutil.which("pinentry-gtk") or "pinentry"
DIR = os.environ.get("PINENTRY_RBW_DIR") or os.path.expanduser("~/.config/rbw")
TIMEOUT = float(os.environ.get("PINENTRY_RBW_TIMEOUT", "30"))
TOAST = os.path.expanduser("~/.local/share/pinentry-rbw/toast.ps1")
PS = "/mnt/c/Windows/System32/WindowsPowerShell/v1.0/powershell.exe"


def toast(*args):  # WSL2: Windows toast; fire and forget, never blocks the unlock
    if not (os.path.isfile(TOAST) and os.access(PS, os.X_OK)):
        return False
    win = subprocess.run(["wslpath", "-w", TOAST], capture_output=True, text=True).stdout.strip()
    subprocess.Popen([PS, "-NoProfile", "-NonInteractive", "-ExecutionPolicy", "Bypass",
                      "-File", win, *args], cwd="/mnt/c", start_new_session=True,
                     stdin=subprocess.DEVNULL, stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)
    return True


def enc(s):  # Assuan percent-encoding for D and SETDESC lines
    return s.replace("%", "%25").replace("\r", "%0D").replace("\n", "%0A")


def decrypt():
    agefile, ident = os.path.join(DIR, "master.age"), os.path.join(DIR, "yubikey-identity.txt")
    for f in (agefile, ident):
        if not os.path.isfile(f):
            return None, "no " + f
    hook = os.environ.get("PINENTRY_RBW_DECRYPT")  # test hook
    cmd = hook if hook else ["age", "-d", "-i", ident, agefile]
    shown = toast()
    p = subprocess.Popen(cmd, shell=bool(hook), stdin=subprocess.DEVNULL, stdout=subprocess.PIPE,
                         stderr=subprocess.PIPE, start_new_session=True)
    try:
        out, err = p.communicate(timeout=TIMEOUT)
    except subprocess.TimeoutExpired:
        os.killpg(p.pid, signal.SIGKILL)
        p.communicate()
        return None, "timed out after %ds waiting for the touch" % TIMEOUT
    finally:
        if shown:
            toast("-Clear")
    if p.returncode != 0:
        last = (err.decode(errors="replace").strip().splitlines() or ["exit %d" % p.returncode])[-1]
        return None, "YubiKey decrypt failed: " + last[:160]
    value = out.decode().rstrip("\r\n")
    return (value, None) if value else (None, "YubiKey decrypt returned an empty value")


def relay(lines, reason):
    if reason:
        print("pinentry-rbw: " + reason, file=sys.stderr)
        lines = [l + "%0A%0A(pinentry-rbw: " + enc(reason) + ")" if l.startswith("SETDESC ") else l
                 for l in lines]
    p = subprocess.Popen(shlex.split(REAL) + sys.argv[1:], stdin=subprocess.PIPE)
    p.communicate("".join(l + "\n" for l in lines).encode())
    return p.returncode


def main():
    lines = []
    for raw in sys.stdin:  # rbw writes everything, then closes stdin
        lines.append(raw.rstrip("\n"))
        if lines[-1].startswith("GETPIN"):
            break
    first_try_master = ("SETPROMPT Master Password" in lines
                        and not any(l.startswith("SETERROR") for l in lines))
    if not first_try_master:
        return relay(lines, None)
    value, reason = decrypt()
    if value is None:
        return relay(lines, reason)
    out = ["OK Pleased to meet you"]
    for l in lines:
        if l.startswith("GETPIN"):
            out.append("D " + enc(value))
        out.append("OK")
    sys.stdout.write("".join(l + "\n" for l in out))
    return 0


if __name__ == "__main__":
    sys.exit(main())
```

The toast is optional. WSL has no notification daemon (`notify-send` fails with `org.freedesktop.DBus.Error.ServiceUnknown`), so the wrapper calls Windows PowerShell 5.1 through WSL interop and shows a WinRT toast instead, then removes it once the decrypt returns. Save this as `~/.local/share/pinentry-rbw/toast.ps1`; without the file the wrapper skips the toast and the key's blinking light is the only prompt:

```powershell
# toast.ps1 - Windows toast for pinentry-rbw on WSL2 (WSL has no notification
# daemon, so notify-send has nowhere to go). Windows PowerShell 5.1 (WinRT).
#   toast.ps1 -Title rbw -Body '...' [-Icon <png path, UNC ok>]   show
#   toast.ps1 -Clear                                             remove it
# The icon is copied to %LOCALAPPDATA%\pinentry-rbw\ because toast images must
# be local files. Tag/group keep one toast at a time and let -Clear find it.
param(
    [string]$Title = 'rbw',
    [string]$Body = 'Touch the YubiKey to unlock rbw',
    [string]$Icon = '',
    [int]$Seconds = 35,
    [switch]$Clear
)
$ErrorActionPreference = 'Stop'
[Windows.UI.Notifications.ToastNotificationManager, Windows.UI.Notifications, ContentType = WindowsRuntime] | Out-Null
[Windows.Data.Xml.Dom.XmlDocument, Windows.Data.Xml.Dom.XmlDocument, ContentType = WindowsRuntime] | Out-Null
$app = '{1AC14E77-02E7-4E5D-B744-2EB1AE5198B7}\WindowsPowerShell\v1.0\powershell.exe'
$tag = 'touch'
$group = 'pinentry-rbw'

if ($Clear) {
    [Windows.UI.Notifications.ToastNotificationManager]::History.Remove($tag, $group, $app)
    exit 0
}

$logo = ''
if ($Icon -and (Test-Path -LiteralPath $Icon)) {
    $dir = Join-Path $env:LOCALAPPDATA 'pinentry-rbw'
    $dst = Join-Path $dir 'icon.png'
    New-Item -ItemType Directory -Force -Path $dir | Out-Null
    if (-not (Test-Path -LiteralPath $dst) -or
        (Get-Item -LiteralPath $dst).Length -ne (Get-Item -LiteralPath $Icon).Length) {
        Copy-Item -LiteralPath $Icon -Destination $dst -Force
    }
    $uri = ([System.Uri]$dst).AbsoluteUri
    $logo = "<image placement='appLogoOverride' src='$uri'/>"
}

$esc = [System.Security.SecurityElement]
$xml = New-Object Windows.Data.Xml.Dom.XmlDocument
$xml.LoadXml("<toast scenario='reminder'><visual><binding template='ToastGeneric'>$logo<text>$($esc::Escape($Title))</text><text>$($esc::Escape($Body))</text></binding></visual><actions><action content='Dismiss' arguments='dismiss' activationType='system'/></actions></toast>")
$t = New-Object Windows.UI.Notifications.ToastNotification $xml
$t.ExpirationTime = [DateTimeOffset]::Now.AddSeconds($Seconds)
$t.Tag = $tag
$t.Group = $group
[Windows.UI.Notifications.ToastNotificationManager]::CreateToastNotifier($app).Show($t)
```

An optional `-Icon` PNG (a UNC `\\wsl.localhost\...` path is fine) is copied to `%LOCALAPPDATA%\pinentry-rbw\` and shown from there as the toast's logo. The AppUserModelID is Windows PowerShell's own, so the toast needs no app registration.

## Part 7: point rbw at the wrapper and test it

```bash
rbw config set pinentry "$HOME/.local/bin/pinentry-rbw"
rbw lock && rbw unlock && rbw unlocked && echo unlocked
```

`rbw unlock` blocks until you touch the key. Measured on this box, from `rbw unlock` starting to it returning, touch included: 3 s and 10 s on two runs. `rbw config set` stops the agent, so the next command starts one that reads the new setting[^rbw-config]. A full path keeps the wrapper independent of the agent's `PATH`.

## Verification

| Check | How | Expected |
|---|---|---|
| Key attached to WSL | `cat /sys/bus/usb/devices/*/product` | a line `YubiKey OTP+FIDO+CCID` |
| pcscd lets you in | `ykman list` | `YubiKey 5 ... Serial: <serial>`, no `PC/SC not available` |
| gpg reaches the card | `gpg --card-status` | `Reader ...: Yubico YubiKey ...`, no `No such device` |
| Age key present | `age-plugin-yubikey --list` | `Name: rbw-unlock`, slot 1 |
| Round trip | `age -d -i ~/.config/rbw/yubikey-identity.txt ~/.config/rbw/master.age \| wc -c` (touch) | the password's length; nothing printed but the count |
| Unlock by touch | `rbw lock && rbw unlock` | toast, touch, exit 0; `rbw unlocked` exits 0 |
| Fallback (offline-tested only, see below) | `usbipd detach --busid <busid>`, then `rbw lock && rbw unlock` | the `pinentry-gtk` dialog, its text ending in `(pinentry-rbw: YubiKey decrypt failed: ...)`; typing the password unlocks |

Offline, the wrapper's decision logic is testable without a key: feed it rbw's exact command sequence on stdin with a fake real pinentry and a fake decrypt command, and check that the first-try prompt gets a `D` line while a `SETERROR` retry, a different prompt, a failing or empty decrypt, a decrypt that outlives the timeout, and a missing `master.age` each reach the fake pinentry. The version above passes those ten cases; the touch-to-unlock timings were measured with a longer variant of the same wrapper.

## What protects what

| Asset | Protected by |
|---|---|
| The P-256 private key | Generated on the YubiKey, not exportable |
| `master.age` on disk | Useless without that key; decrypting needs the key present and a touch |
| Use of the key | Physical touch per decrypt (touch policy `always`); no PIN, by choice (see Constants) |
| Managing the PIV applet (new keys, changing policy) | The PIN, which now also guards the management key |
| Unlocking rbw without the key | The master password, typed, exactly as before |

A process on the box can start the decrypt of a locked rbw but cannot finish it without a touch. Someone at the desk with the key attached can unlock with one touch. Once rbw is unlocked none of this applies: the agent answers any process of the same user, as it did before. With rbw's `lock_timeout` at 86400 s on this box, one touch covers a day of reads.

## Gotchas and lessons learned

- While the key is attached to WSL, Windows does not see it: passkeys and WebAuthn in Windows browsers stop working until `usbipd detach`. The attach does not survive a reboot or a replug. The plugin's README documents the other route for WSL: install `age-plugin-yubikey.exe` on Windows and call it from the WSL `age` through interop, which keeps the key on the Windows side[^ayk-readme]. It uses the same PIV key and the same `master.age`; not tried here yet.
- A PIV PIN longer than 8 characters fails as `size error`, not as a wrong PIN, and costs no attempt.
- Firmware 5.7's AES192 default management key looks like a custom key to age-plugin-yubikey 0.5.1. `change-management-key -a tdes --protect` before generating.
- The plugin's PIN dialog wants a real terminal. Inside an agent harness's pseudo-terminal it was interrupted (exit 130) or printed nothing.
- `notify-send` has nowhere to go on WSL; the toast goes through `powershell.exe`, which interop starts in about 0.2 s, detached so it never delays the unlock.
- The wrapper must never answer a retry. If `master.age` is stale (the master password changed), answering every prompt would spend all three attempts in under a second; answering only the first spends one and hands the rest to the dialog.
